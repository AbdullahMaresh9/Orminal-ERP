   345→## **Navigation Governance Rules**
   346→
   347→-   Every main module must provide an overview workspace and an
   348→    exception-centered work queue.
   349→
   350→-   No frequent operational task should require more than three
   351→    navigation levels from the role workspace.
   352→
   353→-   Every posted document must expose source document, target document,
   354→    accounting impact, inventory impact and audit trail.
   355→
   356→-   Advanced search must support company, branch, status, date, user,
   357→    partner, item, warehouse, amount and approval state.
   358→
   359→-   Saved filters must be personal, team-level and system-level with
   360→    permission control.
   361→
   362→-   Breadcrumbs must show functional path and document lineage, not
   363→    merely URL hierarchy.
   364→
   365→-   Configuration screens must be searchable but hidden from operational
   366→    roles unless authorized.

   484→## **Recommended Enterprise UX Approach**
   485→
   486→Adopt a hybrid UX philosophy: SAP Fiori-like role workspaces and
   487→analytical/object page discipline; Odoo-like smart buttons and activity
   488→feeds; Business Central-like command search and productivity
   489→integration; NetSuite-like saved searches and role dashboards;
   490→ERPNext-like DocType consistency and workflow visibility. This
   491→recommendation is a design pattern, not a claim that one vendor natively
   492→combines all patterns.

   680→## **Enterprise Data Governance Standards**
   681→
   682→-   Single source of truth must be explicitly assigned for every master
   683→    object.
   684→
   685→-   Data stewardship roles must be defined for finance, products,
   686→    partners, warehouses, HR and security.
   687→
   688→-   Naming standards must cover table/entity names, document codes, API
   689→    names, events, statuses and reason codes.
   690→
   691→-   Data quality rules must include completeness, uniqueness, validity,
   692→    consistency, timeliness and referential integrity.
   693→
   694→-   Soft delete is prohibited for posted legal documents; use archive,
   695→    cancel, reverse or block.
   696→
   697→-   Versioning is mandatory for tax rules, price lists, cost rates,
   698→    BOMs, routings, approval matrices and workflow definitions.
   699→
   700→-   Data lineage must connect source documents, postings, reports, API
   701→    messages and analytical datasets.
   702→
   703→-   Data classification must mark public, internal, confidential,
   704→    restricted and regulated data.
